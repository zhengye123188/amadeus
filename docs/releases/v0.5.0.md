# Research CLI v0.5.0

本版为交互式科研终端增加按工具职责分工的多 Agent 协作和本地 OCR。主 Agent 根据当前问题动态委派，用户仍可从任意问题开始或随时转向。

## 多 Agent 协作

复用固定版本 `pi-subagents@0.74.0` 的前台执行器，并提供受控 Pi 子会话。文献、文档、代码、实验分析、记忆和审阅六种角色使用各自工具白名单；支持并行委派、保留历史的追问、状态查询和取消。

子 Agent 继承主会话实际选择的模型、认证、推理等级、工作区及科研服务；主/子共用模型步数、时间、token 和费用软预算。子 Agent 可读取、检索和导入资料；代码修改、记忆更新和实验执行由主 Agent 完成，并沿用原审批机制。子 Agent 的意见不会自动成为证据或人工确认。

```text
让文献 Agent 比较相关论文，同时让代码 Agent 分析当前实现，再汇总可验证的改进方向。
/agents
/agents roles
/agents cancel agent_任务编号
```

每次最多并行三项，每会话最多保留十六个子 Agent。委派在前台等待，不提供脱离终端运行的后台 Agent 或嵌套委派；退出进程后不恢复子 Agent 历史。科研来源、记忆、证据和实验记录继续保存在项目 `.research` 中。执行器的内部 API 通过版本和文件哈希固定，升级需要重新审查。

## 本地 OCR

复用现有 `pi-docparser@4.0.0` / LiteParse 2.10.1 内的 Tesseract 引擎。支持英语、简体中文和繁体中文，不需要云端 OCR 账号或额外 Tesseract 可执行文件。

```sh
# npm/源码安装首次使用时显式下载语言数据
research ocr install --languages eng,chi_sim
research ocr list
# 繁体中文按需安装
research ocr install --languages chi_tra
```

v0.5.0 独立安装器内置三种语言数据及 Apache-2.0 许可。语言数据来自官方 `tessdata_fast` 的固定 commit，下载时核对大小与 SHA-256；解析阶段不隐式下载，也不上传文档。模型缺失或损坏会明确报错。

OCR 默认关闭，需在对话中明确要求，例如“使用英文和简体中文 OCR 导入 papers/scan.pdf”。每份 OCR PDF 最多 20 页、20 MB；普通文本型 PDF 仍最多 200 页。来源记录保存原文件哈希、页码、OCR 引擎、语言及语言模型哈希。真实英文/中文扫描件已用于工程验证；公式、复杂布局和引用文字仍需核对原页。

## 工具与分发

默认联网配置为 **53 个科研 MCP 工具、3 个文件工具、6 个原生包工具和4个协作工具，共66个**。配置 embeddings 可再增加两个科研 MCP 工具；离线配置和用户白名单会改变可见集合。OCR 使用现有 `import_document` / `download_arxiv`，没有增加重复的文档工具。

npm 分发携带科研后端源码，安装需要 Node ≥22.19 和 uv；独立安装器内置 Node 22.23.1、Python 3.12.14、npm/npx、Pi 0.99.1、科研后端与四个 Pi 包。npm 和 GitHub Release 分别发布，不自动更新 PyPI。
